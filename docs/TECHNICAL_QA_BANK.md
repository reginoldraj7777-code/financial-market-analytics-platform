# Technical Interview Q&A Bank

## Why is a market-data project relevant to GTM Operations?

The business domain is different, but the analytical pattern is reusable: multiple entities, time-based KPIs, movement, variability, unusual changes, SQL reporting, prioritization, and stakeholder communication. In the synthetic GTM layer, symbols become regions, accounts, products, segments, or sales teams, while returns and volatility become changes in pipeline, bookings, win rate, conversion, or activity.

## What exactly did AI do?

AI supported bounded tasks such as traceback diagnosis, repository-aware review, SQL review planning, documentation structure, and business translation. I retained responsibility for architecture, accepted or rejected changes, verified calculations, ran tests, and reviewed final outputs.

## Why Cursor?

Cursor can use repository context. I combine that advantage with version-controlled project rules, explicit file references, plan-before-edit workflow, line-by-line diff review, tests, and documentation. This makes adoption safer and more repeatable for a team.

## Why Snowflake?

Snowflake represents the governed warehouse layer for reusable regional analysis. The project demonstrates environment-based configuration, query tagging, governed views, Snowflake-native SQL, read-only analysis, and optional synthetic-data upload. The local demo remains stable without requiring credentials.

## How do you validate AI-generated SQL?

I inspect referenced tables and columns, review filters and date scope, check window partitions, run read-only queries on synthetic or approved data, compare results with independent calculations, and document assumptions before using the output.

## What would you improve in production?

I would add role-based access, approved data contracts, orchestration, observability, CI/CD, automated data-quality thresholds, cost monitoring, user analytics, formal model-risk review, and measured adoption KPIs.
